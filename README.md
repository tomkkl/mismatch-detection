# AgentLint

Detect LLM agent tools whose **code does more than their interface says** (name + parameter
schema + description). CSCI 566, Fall 2026.

Example: a tool described as "List the files in a project folder" that also moves the whole
directory. The code is fine on its own and the description is fine on its own. Only the pair
is wrong.

Existing scanners can't catch this. Agent Audit, the main baseline, is rule-based and never
compares a tool's description with what its code does. In our probes it reported nothing on
capability mismatches.

`CLAUDE.md` has the full team notes: decisions and the reasons behind them, dataset details,
verified facts about Agent Audit, and gotchas.

## Approach

- **Model:** a GraphCodeBERT cross-encoder (`microsoft/graphcodebert-base`). The description
  and code go in together as one input, and a classification head says mismatch or not.
- **Effect classes:** read · modify · destroy · relocate · send outward · execute ·
  spend/transact · change authority. The set is small and closed, but the code that produces
  each effect is unbounded. That's why we learn it instead of writing rules.
- **Training data:** generated by an LLM (Claude Sonnet 5.5), then checked with the AST. See
  below.
- **Baseline:** Agent Audit, framed as coverage: run both on the same set and report what each
  catches.

## Quick start

```
git clone https://github.com/tomkkl/mismatch-detection.git
cd mismatch-detection
python3 -m venv .venv
.venv/bin/pip install -e ".[dev,baseline]"      # Windows: .venv\Scripts\pip install -e ".[dev,baseline]"
pytest
```

Python 3.10+ (developed on 3.13). `baseline` installs Agent Audit v0.19.2. Training runs on
Colab.

## The training dataset

The dataset comes with the clone (~25 MB):

| Path | What it is |
|---|---|
| `data/splits/full/{train,val,test}.jsonl` | the splits to train and evaluate on |
| `data/generated/full/pairs.jsonl` | all pairs |
| `data/generated/full/stats.json` | counts and shortcut baselines |
| `data/generated/full/rejects.jsonl` | what was filtered out and why |
| `data/generated/llm_cache/` | cached LLM answers, so rebuilds make no new calls |

**2,572 description + code pairs from 763 generated tools; 689 (26.8%) are mismatches.**
Each honest tool produces up to 5 pairs:

| Pair (`mutation`) | Code | Description | Label |
|---|---|---|---|
| original (`null`) | honest | original | honest |
| `inject_code` | honest + one added operation | rewritten from the honest code, so it doesn't mention the operation | **mismatch** |
| `declare_effect` (twin) | same as `inject_code` | rewritten to mention the added operation | honest |
| `honest_rewrite` | honest | same as `inject_code` | honest |
| `weaken_description` | honest | one declared effect removed | **mismatch** |

The same code appears with both labels, and so does the same description, so the model can
only get it right by comparing the two. Descriptions are length-matched so length can't give
the label away. A length-only classifier (72.6%) and a description-only one (74.2%) both score
about the same as always guessing "honest" (73.2%).

- **Injected mismatches (560):** 7 effect classes, 91–105 each. `read` is not injected: an
  extra read rarely matters unless the data leaves, which `send outward` covers. Spread evenly
  over 4 positions: start, middle, end, and inside a helper.
- **Weakened mismatches (129):** fewer, because many tools had no effect that could be removed.
- **Splits by tool**, so a tool and all its variants stay together:

| Split | Pairs | Tools | Mismatch |
|---|---|---|---|
| train | 2,062 | 610 | 26.7% |
| val | 259 | 76 | 28.2% |
| test | 251 | 77 | 26.3% |

Each row has `description`, `code`, `params`, `mismatch` (label), `undeclared` (hidden
effect), `mutation` (pair type), `injected_lines`, and `source_id` (groups a tool's pairs).

### Rebuilding or extending it

Generation runs through the `claude` CLI (log in with `claude` first), so it uses a Claude
plan's usage, not the paid API. Settings are in `configs/datagen.yaml`.

```
agentlint data build configs/datagen.yaml --tag full --n-honest 800
```

Output goes to `data/generated/<tag>/` and `data/splits/<tag>/`. With the committed cache,
rebuilding `full` makes no LLM calls. Rebuilding overwrites the committed files, so the diff
shows up in git. If a usage limit stops a new run, rerun the same command later: finished calls
are cached and reused.

## Evaluation plan

Test sets, each reported separately:

1. held-out generated pairs (`data/splits/full/test.jsonl`)
2. pairs from a different LLM (Claude Opus 5.5), same recipe
3. real GitHub tool functions with an injected capability

Plus an Agent Audit coverage set. Metrics: precision / recall / F1 on the mismatch class,
PR-AUC, and **group accuracy** (every pair from one source tool right). We also report
GraphCodeBERT before vs after fine-tuning. Tune on `val`; score each test set once.

## Layout

```
src/agentlint/
  schema.py          effect classes, ToolPair record
  effects.py         effect definitions + word lists (soft label checks, localization)
  data/
    llm.py           claude CLI backend (plan usage) with on-disk cache
    generate.py      LLM-generated honest tools
    mutate.py        make mismatches (inject code / honest twin / weaken description)
    verify.py        code normalization (AST round-trip) + AST label checks
    split.py         group split by source (never random)
    build.py         pipeline: generate -> verify -> mutate -> split
  model/             (stubs) dataset, GraphCodeBERT cross-encoder, training loop
  eval/              (stubs) metrics, Agent Audit coverage run
  localize.py        AST: which lines carry the undeclared effect
  cli.py             `agentlint` entry point
configs/             datagen.yaml (dataset), binary.yaml / multilabel.yaml (training)
data/                datasets; only `full` and the LLM cache are committed
probes/              Agent Audit probe scripts; generated cases go in probes/aa_run/
notebooks/           Colab training notebooks
scripts/             one-off utilities
tests/               unit tests
docs/                proposal (pre-proposal; parts are out of date, see CLAUDE.md)
```
